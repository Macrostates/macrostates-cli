# Annex: legacy document cleanup

Read this procedure only when cleanup of existing documentation is authorized.
New material must already follow [Public document authoring](004_documents.md).
Package adoption alone does not authorize document cleanup, consumer updates or
rewriting repository history.

## Establish the authorized scope

Identify the current documentation, generated artifacts, ignored reports, drafts,
media and archives covered by the request. Include relevant templates and links.
Use a safe repository-relative inventory or generic labels; do not create an
inventory that repeats identifying names. State what was actually inspected and
which evidence or archive formats remain unavailable.

Keep unrelated application data, installed dependencies, other repositories and
Git history outside the cleanup. Do not patch immutable imported specification
packages or rewrite integrity locks to hide a change; use their canonical source
and the selected package-update procedure. Preserve legal notices and necessary
public technical provenance under the central contract's narrow exceptions.

## Transform current documents

1. Read the scoped artifact into memory. Preserve its technical objective,
   decision, reason, scope, dates, status, acceptance state, actual measurements,
   failures and qualification limits.
2. Replace conversational material with a neutral technical summary and use role
   attribution. Remove personal context, identifying configuration and inaccessible
   contextual references. Use repository-relative locations or descriptive
   placeholders. Preserve relationships only when technically necessary.
3. Review names and structured keys as well as values. Apply the same checks to
   logs, commands, filenames, metadata, media and nested archive members. If a
   document's name is identifying, rename it neutrally and repair local links
   without retaining an identifying old-name alias or reversal map.
4. Serialize only reviewed content. Remove obsolete generated material within
   the authorized document scope, including raw copies, backups and private
   alternative editions. Do not leave a private original in an ignored location.
5. Parse rewritten structured formats, verify local links and check that no
   technical requirement or lifecycle distinction was silently changed. A cleanup
   does not authorize completing a workflow, accepting a baseline, passing a test
   or publishing a release. Preserve an existing open state if confirmation is
   unavailable.

Do not retain transcripts or a private-to-public identity mapping as cleanup
evidence. A neutral account of the applied rules and technical limits is enough.

## Historical evidence and integrity

Mark rewritten receipts as `Anonymized historical summary`. Keep original counts
and observed outcomes when relevant, but do not imply a fresh run or reproducible
fixture when the original inputs are unavailable. State the missing qualification
directly. Remove unavailable contextual links or label the evidence unavailable;
do not replace them with fictional receipts.

An original recorded digest is only a historical observation after its document
has been redacted. Do not relabel it as the current document's digest or recompute
it from fabricated inputs. A new sanitized artifact's digest, if needed, identifies
that artifact separately and does not verify the original run.

Current documentation cleanup must not rewrite original commits, published tags,
historical baseline byte bindings or successful publication identities. Original
record bytes remain at their original commits and tags; this procedure does not
erase Git objects. Do not silently modify a hash-bound record or active candidate
plan to make an integrity check pass. Finish any necessary pre-plan sanitization
before binding new records. If current legacy artifacts require an explicit
migration or replanning, record that technical requirement and perform only the
authorized supported procedure; otherwise report the blocked integrity gate.
Never claim that a redacted summary is an unchanged consumed record.

## Completion evidence

Review the complete authorized inventory, including ignored outputs and nested
archives. Use the central contract's safe diagnostics without echoing removed
content. Verify parsing, local links, package metadata/provenance where relevant,
required exceptions and the retained acceptance/closure distinctions. Report
only role-attributed technical results, reviewed scope, remaining evidence limits
and any unresolved privacy or integrity condition. Use
[the acceptance matrix](resources/document-authoring-acceptance.md) to review
representative cases; do not report it as an executed test without actual results.
