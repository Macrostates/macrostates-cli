# Verification expectations

Follow Python-library for dependencies, formatting, linting, types, packaging,
tests, examples and documentation. Commit contributor dependency locks and run
relevant quality checks in CI. Verify these CLI-specific observable outcomes:

- Public factories/exports, reports/diagnostics, source injection and imports
  without project/network/logging side effects.
- Installed help/version/commands, human/JSON results, success/check/error exits,
  and command/API agreement.
- Modern/legacy discovery, ambiguity refusal, historical metadata and selected
  policy isolation, including unknown future formats/policies.
- Explicit initialization, preserved extensions/instructions, safe paths and no
  unintended application or Git changes.
- Dependencies, cycles, entrypoints, orders, links and independent scope boundaries.
- Canonical install/lock, offline integrity and executable flags, clean upgrades,
  missing-copy restoration, moved-tag refusal, edit preservation and rollback.
- Exact staged-index checks rather than working-tree contents.
- Release declarations, build isolation and installed API/wheel behavior outside
  the checkout across supported Python versions.
- Generic Git sources using annotated tags, exact inventories, moved/lightweight
  tag refusal, external authentication, and credential-safe failures.
- Captured work origin, explicit late provenance, impact/coverage records, and
  development identities without automatic version allocation.
- Optional deliverable defaults and independent policies, retained historical
  provenance, and Android counter ordering.
- Development-branch merge/rebase synchronization, cached/fetched state, primary
  guards, dirty/detached/active-operation refusal, and conflict preservation.
- Numbered closure requests and documentary workflow/history gates, including
  renamed records and missing authorization evidence.
- Exact combined integration contents, explicit scope decisions, stale target
  refusal, and separate external review/check requirements.
- Target/tree-bound baseline plans, impact aggregation, recoverable preparation,
  evidence/history preservation, candidate collisions, exact baseline snapshots,
  integrated publication identities, and explicit idempotent migration.
- Independent CLI application build versions, development status, verified shipped
  source binding, and archive rebuilding without Git or application imports.

The CLI's composition selects explicit official releases as unchanged tracked
archives with a verified lock, plus editable local CLI requirements. Adopt new
release policies explicitly when their canonical releases and tooling are ready;
do not claim a draft dependency has been published or silently rewrite a lock.
Working/staged self-checks exercise the selected behavior. Keep historical
fixtures; upstream adoption never silently migrates other projects.

Maintain conformance mapping and dated evidence in implementation documentation,
distinguishing tests, manual review and coverage limitations. Structural checks
or a coverage percentage alone do not establish implementation conformance.
This expectation does not add an automatic semantic-conformance command.
